## Why

哈密瓜目前是**纯单人 AI 陪练**。单人模式的安全感是核心优势，但缺少「人际关系」这层留存抓手——用户练完即走，没有继续回来的社会性理由。

我们希望引入**结构化社交**（而非开放社区）：用「瓜友」关系把用户绑定在练习行为上。核心设计原则是 **用系统设计本身阻止社区变质，而不是靠人工内容审核**——因为开放社区的内容生产成本为零、学习内容成本极高，必然劣币驱逐良币。

本变更是「瓜友」的 **Phase 1**：包含**异步关系层** + **实时练习房间**。明确**不做**自由 UGC、不做对抗排名——这些放到后续阶段。

> 关键技术判断：本应用 STT 用**浏览器端 Web Speech API**（本地识别）、TTS 客户端播放，因此实时双排**不需要 WebRTC 音频混流**——每人本地把语音转文字，经现有 **WS :3001** 同步到「练习房间」与 AI，本质是「**多人共享对话会话 + 服务端轮次同步**」。复杂度从「WebRTC 多方音频」降为「WS 状态同步」，可最大化复用现有单人对话架构。Phase 1 双排中搭子之间**以文字呈现**彼此发言（不传原声）；听到原声需 WebRTC，留待后续阶段。
>
> 流动性风险规避：实时双排面临**同水平/同时区/同时在线**的冷启动问题，因此 Phase 1 **异步层是基础、实时房间是增强**——即使凑不齐两人，异步瓜友关系仍可独立运转；并通过**种子瓜友（demo buddies）**让功能在零真实用户时也不空。

## What Changes

- **瓜友发现（结构化匹配）**：按学习维度匹配——CEFR 水平（±1 级，必须相近）+ 可选（目标场景 / 练习时段 / 母语背景）。**禁止**按性别、年龄、头像照片筛选，从根源断掉交友动机。
- **瓜友卡片（只露学习数据）**：发现页只展示对方的 **本周练习次数 / 擅长场景 / CEFR / 最近雷达图 + 系统 avatar + 昵称**。**没有**发帖、评论、动态、真人照片，无内容生产空间。
- **瓜友关系（靠行为建立与维系）**：发起「邀请成为瓜友」→ 对方接受 → 成为瓜友。关系因长期不练而**冷却**（降级提示），促使双方保持练习。
- **预置语音贴纸鼓励（Phase 1 无自由 UGC）**：看到瓜友练习记录后，可发送**系统预置**的语音/文案贴纸（如「Nice job!」「再来一颗瓜！」）。第一版**不开放**自由录音/自由文字，杜绝骚扰与审核成本。
- **瓜友排行 + 瓜友连胜**：仅在瓜友之间展示「本周练习次数」排行；双方都坚持练习时累计「瓜友连胜」天数。**没有**全站明星 / KOL / 粉丝数体系。
- **实时练习房间（双排 · 协作模式）**：两位瓜友进入同一场景房间，与同一个 AI 轮流对话、协作完成任务（如一起在餐厅：一人点菜、一人问价）。基于 **WS 轮次同步**，每人本地 STT 后将文字广播至房间与 AI；房间内**无文字聊天框**，唯一沟通方式是说英语（本来就是目的）。支持邀请瓜友入房 / 在线匹配入房，一方掉线时房间优雅降级。
- **种子瓜友**：系统内置若干拟真练习记录的 demo 瓜友，解决冷启动空窗，并支撑 Demo 演示。
- **登录门槛**：瓜友为多用户功能，**仅登录用户可用**；游客模式（localStorage）保持单人体验，引导登录后解锁瓜友。

### 明确不做（Out of Scope，留待后续阶段）

- ❌ 实时**角色互换 / 对抗模式**——复用房间设施紧随其后；对抗模式因对焦虑用户负向，做成 opt-in
- ❌ 双排中听到搭子**原声**（WebRTC 音频）——Phase 1 仅文字呈现
- ❌ 自由语音 / 自由文字内容——后续（需 ASR 审核 + 举报拉黑）
- ❌ 约练习 / 守约信誉分——后续
- ❌ 全站社区、动态流、好友聊天

## Capabilities

### New Capabilities

- `melon-buddy-discovery`：瓜友匹配算法（学习维度）与瓜友卡片展示（只露学习数据）
- `melon-buddy-relationship`：瓜友邀请 / 接受 / 解除、关系冷却机制、登录门槛
- `melon-buddy-encouragement`：预置语音贴纸鼓励的发送与接收（无自由 UGC）
- `melon-buddy-ranking`：瓜友本周练习次数排行与瓜友连胜
- `melon-buddy-live-room`：实时练习房间（双排协作）——房间生命周期、入房（邀请/匹配）、WS 轮次同步、掉线降级

### Modified Capabilities

- （无现有主规格被修改；用户/会话相关为新增能力的依赖）

## Impact

- **后端（`server/`）**
  - Prisma schema 新增模型：`Buddy`（关系）、`BuddyRequest`（邀请）、`Encouragement`（贴纸记录）；可能扩展 `User` 的可公开字段（昵称、avatarKey、CEFR、母语、目标场景、练习时段）
  - 新增 API 路由：匹配候选、发起/响应邀请、解除瓜友、发送贴纸、瓜友排行、瓜友连胜
  - 周练习次数聚合（基于现有 Session 记录）
  - **WS 房间层**：在现有 WS 服务上新增「练习房间」频道——房间创建/加入/离开、轮次（whose-turn）仲裁、用户发言广播、AI 回复广播、掉线降级
  - 种子脚本：写入 demo 瓜友
- **前端（`web/`）**
  - 新增「发现 / 瓜友」页（AppShell 内，新增底栏/侧栏入口）
  - 组件：瓜友卡片、匹配筛选、预置贴纸选择器、瓜友排行
  - **实时房间页**（全屏，AppShell 外，类似 `/conversation`）：双人头像 + 轮次指示 + AI 对话区 + 无文字聊天框
  - 复用现有 [`user-avatar.tsx`](web/src/components/user-avatar.tsx)（8 个系统 avatar）、雷达图组件与现有对话/STT/TTS 流水线
  - 登录门槛引导
- **共享（`shared/contracts.ts`）**
  - 新增瓜友相关 DTO、预置贴纸枚举、**房间 WS 消息协议**（join/leave/turn/utterance/ai-reply/peer-disconnect 等）
- **依赖**：无新增第三方依赖（沿用 Express + Prisma + React + ws）；实时**不引入 WebRTC**
