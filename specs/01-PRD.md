# PRD · AI 英语口语陪练工具

> 产品需求文档（Product Requirements Document）。回答"**为谁、做什么、为什么、做到什么程度算成功**"。
> 本文是所有设计与实现的源头。AI 在实现功能时，必须能追溯到本文的某条需求。
>
> **版本说明**：v2 起产品目标从"黑客松 Demo"升级为"可投入使用的产品"，纳入账号体系、云端持久化与跨端能力（见第 7、8 节）。

---

## 1. 产品概述

| 项 | 内容 |
|----|------|
| 产品名 | AI 英语口语陪练（Speak Coach） |
| 一句话定位 | 一个有耐心、懂教学、能记住你的 AI 外教，在真实场景中陪你开口说英语并给出可量化反馈 |
| 目标用户 | 有一定英语基础但缺乏真实开口环境、想提升口语的学习者 |
| 核心价值 | 随时可练的真实场景对话 + 不打断的智能纠错 + 看得见的成长反馈 |
| 项目背景 | 起于黑客松题目一，v2 目标为产品化（多用户、跨端、可持续运营） |

---

## 2. 用户画像与核心痛点

| 用户 | 痛点 |
|------|------|
| 求职者小李 | 要英文面试，但没人陪练，紧张到说不出话 |
| 留学生小王 | 日常点餐/看医生等场景听不懂、说不对 |
| 职场人小张 | 要参加英文会议，缺乏表达训练和反馈 |

**共同痛点**：① 没有真实对话场景 ② 不知道自己错在哪 ③ 看不到进步、缺乏动力。

## 3. 用户故事（User Stories）

> 格式：作为 \<角色\>，我想要 \<功能\>，以便 \<价值\>。每个故事带验收标准（AC）。

### US-01 选择练习场景
> 作为学习者，我想从预设场景中选择一个，以便针对性练习。

**验收标准 AC：**
- AC1：首页展示 ≥ 3 个场景卡片（面试、点餐、会议）。
- AC2：每个场景可选难度（初级/中级/高级）。
- AC3：选择后进入对话页，AI 以对应角色开场白主动发起对话。

### US-02 实时语音对话
> 作为学习者，我想用语音和 AI 自然对话，以便模拟真实交流。

**验收标准 AC：**
- AC1：点击/按住即可说话，支持自动检测说话结束（VAD）。
- AC2：界面实时显示我说的话的字幕（流式）。
- AC3：从我说完到 AI 开始发声，延迟 ≤ 1.5 秒（首包）。
- AC4：AI 回复有语音播放 + 文字字幕。
- AC5：AI 保持角色人设（面试官严肃、店员热情）和对话目标。
- AC6：AI 始终保持自身设定角色，**不被用户提供的名字/信息带偏**（如把用户自报的名字误当成自己的名字）。

### US-03 发音评测
> 作为学习者，我想知道我的发音哪里不准，以便改进。

**验收标准 AC：**
- AC1：每句话给出发音总分（0-100）。
- AC2：标出读得差的单词/音素。
- AC3：提供 4 个维度评分：准确度、流利度、完整度、语调。

### US-04 智能纠错（不打断）
> 作为学习者，我想在不打断对话的前提下被纠错，以便保持流畅又能改进。

**验收标准 AC：**
- AC1：对话过程中**不**实时弹窗打断纠错。
- AC2：仅当出现"沟通阻断级"错误时，AI 以自然重述（Recast）隐性纠正。
- AC3：所有错误被静默记录，用于课后复盘。
- AC4：纠错区分"语法错误"（必须改）与"表达升级"（更地道说法）。
- AC5：每条纠错附**口语化的"为什么"原因解释**（不只给出"原句 → 改句"）。

### US-05 课后总结报告
> 作为学习者，我想在练习后看到一份总结报告，以便了解表现和进步。

**验收标准 AC：**
- AC1：展示本次对话全文 + 逐句批注（错误/建议）。
- AC2：5 维能力雷达图（发音、流利、语法、词汇、任务完成度）。
- AC3：高频错误 TOP3。
- AC4：地道表达升级列表（"你说的" → "更地道的"）。
- AC5：与历史会话对比的**成长曲线**（5 维能力随时间趋势）。
- AC6：**隐性重述回放**："你说的" → "我帮你顺的" 对照。
- AC7：近似 **CEFR 等级估算**（A1–C2，标注"估算"）。
- AC8：**评分充分度门控**——当用户发言样本不足（过短/过少，如少于约 15 词或 2 轮有效发言）时，系统**不得给出高分**，须明确提示"内容太少，无法可靠评估"，且**不计入成长曲线**。

### US-06 递台阶（降低开口焦虑）
> 作为学习者，当我卡壳说不出话时，我想得到不打断的引导，以便敢于开口。

**验收标准 AC：**
- AC1：用户卡壳（默认静默 6 秒）时，AI 不打断，主动给出引导。
- AC2：提供一个开头词/短语 + 2–3 个可点选示例回答（贴合当前提问与难度）。
- AC3：用户一开口（录音或打字）提示立即消失。
- AC4：提示生成失败时静默降级，不影响主对话。
- AC5（待定）：触发时机需进一步调优（连续卡壳/更长阈值），当前默认关闭。

### US-07 账号与登录
> 作为学习者，我想用账号登录，以便我的练习记录与成长数据跨设备保存、且不与他人混淆。

**验收标准 AC：**
- AC1：支持注册/登录（邮箱或手机 + 验证码，或第三方 OAuth，至少其一）。
- AC2：登录后所有会话、报告、成长数据与该账号绑定。
- AC3：支持游客模式体验；登录后可将本地游客数据合并到账号。
- AC4：登出后本地不残留可被他人查看的隐私数据。
- AC5：密码（如有）以哈希存储，鉴权用 token，传输加密。

### US-08 数据隔离与跨端同步
> 作为学习者，我想在不同设备登录都能看到自己的数据，且绝不和别人串。

**验收标准 AC：**
- AC1：所有用户数据按 `userId` 在服务端隔离存储。
- AC2：换设备/浏览器登录后能拉取到历史会话与成长曲线。
- AC3：同一浏览器多账号切换互不污染。

### US-09 练习回放
> 作为学习者，我想回看/回听每次练习，以便复盘。

**验收标准 AC：**
- AC1：每次会话保存完整对话转写，报告页可逐句回看（文本回放）。
- AC2（P2）：保存用户与 AI 音频，报告页可逐句**回放音频**。
- AC3：回放数据按账号隔离，仅本人可见。

### US-10 游戏化激励
> 作为学习者，我想看到练习带来的即时奖励与长期成就，以便保持动力。

**验收标准 AC：**
- AC1：每次练习结束有**即时奖励反馈**（+XP、连击 +1、庆祝动画）。
- AC2：首页展示等级/经验进度条、连续练习天数、每日目标——数据真实，不得用写死的占位值。
- AC3：达成里程碑（连击 7 天、累计 N 次等）解锁成就徽章。
- AC4（P2）：练习日历热力图。

### US-11 多场景与自由话题
> 作为学习者，我想有丰富的场景和自由话题，以便练我真正需要的内容。

**验收标准 AC：**
- AC1：场景库 ≥ 8 个，按分类（职场/生活/出行/考试等）+ 难度组织。
- AC2：支持"**自由话题**"模式：用户输入任意主题即可开练。
- AC3：支持"随机场景"。
- AC4（P2）：AI 可按用户目标动态生成定制场景。

## 4. 功能优先级（MoSCoW）

| 优先级 | 功能 |
|--------|------|
| Must（已交付/必须） | US-01、US-02 实时对话、US-04 集中纠错（含"为什么"）、US-05 报告核心、US-05-AC8 评分充分度、US-02-AC6 角色锚定 |
| Should | US-03 发音评测、US-07 账号、US-08 数据隔离同步、US-10 游戏化、US-11 多场景/自由话题、成长曲线、CEFR 估算 |
| Could | US-09-AC2 音频回放、US-06 递台阶（时机调优后开启）、生词本与间隔复习、可分享成绩卡、成就徽章 |
| Won't（本期仍不做） | 真人外教、支付/订阅体系（产品化后期再评估）、社交排行榜、内容运营后台 |

## 5. 关键非功能需求（NFR）

| 类别 | 要求 |
|------|------|
| 性能 | 语音对话首包延迟 ≤ 1.5s；端到端单轮 ≤ 3s |
| 可用性 | 网络异常时有降级与提示，不白屏 |
| 兼容性 | 支持 Chrome / Edge 最新版（麦克风权限） |
| **数据持久化** | 引入关系型数据库（用户/会话/轮次/报告/纠错）；音频回放用对象存储；数据按 `userId` 隔离 |
| **安全** | 密码哈希、鉴权 token（如 JWT）、HTTPS/WSS 传输加密、最小权限访问 |
| **跨端** | 后端 API 化（REST/WS），前端可通过 PWA / Capacitor 复用同一套代码上移动端 |
| **可扩展** | 架构支持万级用户与持续增长的历史数据；音频存储配生命周期清理策略 |
| 可演示性 | 提供可离线兜底的 Demo 路径（防现场网络问题） |

## 6. 成功指标

- 用户可注册登录，换设备后数据无缝同步、互不串。
- 评委/用户能完成完整闭环（登录 → 选场景/自由话题 → 对话 → 看报告 → 看成长 → 获得奖励反馈）。
- 对话延迟体感"像真人"；报告与成长可视化有"哇时刻"。
- 评分合理：内容不足时不虚高给分。
- 差异化清晰：不打断的纠错哲学 + 可量化成长 + 真实场景。

## 7. 范围边界（避免 AI 跑偏）

**v2 纳入范围（分阶段，见第 8 节路线图）**：账号登录体系、服务端数据库与云端持久化、数据按用户隔离与跨端同步、游戏化激励、多场景与自由话题、（P2）音频回放。

**本期仍明确不做**：真人外教、支付/订阅体系、社交/排行榜、内容运营后台、移动端原生重写（先走 PWA/套壳）。

> AI 实现时若发现需求超出本范围，**必须停下来确认**，不得自行扩展。

## 8. 产品化路线图

| 阶段 | 目标 | 关键内容 |
|------|------|----------|
| **P0 修复** | 体验正确性 | 评分充分度门控（US-05-AC8）、角色锚定 bug（US-02-AC6） |
| **P1 产品化地基** | 多用户可用 | 后端数据库 + 鉴权 + 账号体系（US-07）、数据按用户隔离与同步（US-08）、后端 API 化 |
| **P2 体验增强** | 留存与复盘 | 音频回放（US-09-AC2）、游戏化系统（US-10）、报告页/顶栏/成就 UI 重做 |
| **P3 扩展** | 内容与触达 | 多场景库 + 自由话题（US-11）、跨端（PWA/Capacitor） |

> 每个阶段以独立 openspec 变更立项实施；P1 为后续一切的前置依赖。
